# tension-atoi

**Founder & developer at [gnu.in.labs](https://github.com/gnu-in-labs).**

I build local-first systems for Linux, with a focus on native desktop software, AI infrastructure, bounded automation, and user-owned computing.

My work sits across systems engineering, product design, infrastructure, local inference, and human-computer interaction. I am particularly interested in software that remains inspectable under automation: explicit authority, reproducible state, observable execution, and clear boundaries between what an agent can propose and what it can actually do.

## Current work

My primary project is **Gnosix**, an experimental local-first computing platform built around Linux and Wayland.

The broader program explores:

- native desktop surfaces and system services;
- Rust-based application and runtime architecture;
- local and multi-backend LLM inference;
- capability-scoped agentic execution;
- policy, authorization, and privilege boundaries;
- reproducible system state and release engineering;
- human-readable automation and observability.

The goal is not to put an AI wrapper around a desktop.

It is to investigate what a computer looks like when local intelligence, user authority, system state, and interface design are treated as parts of the same architecture.

## Engineering principles

**Local first.**  
A capable computer should remain useful, intelligible, and controllable without requiring a remote platform to mediate every interaction.

**Explicit authority.**  
Identity, capability, consent, and execution are different concerns. Software should not collapse them into a single “trusted agent” abstraction.

**Inspectability over magic.**  
Automation should expose what happened, what changed, what evidence supports a decision, and how the operation can be reproduced or reversed.

**Native where it matters.**  
I am interested in efficient native software, particularly Rust and Linux-native stacks, when they provide meaningful control over performance, memory, integration, or security boundaries.

**Open systems.**  
Open-source software, documented interfaces, portable data, and self-hostable infrastructure are important parts of long-term user agency.

## AI-assisted engineering

I use coding and research agents extensively.

They help with code exploration, implementation, debugging, research, documentation, testing, and large-scale repository work. I treat them as high-leverage engineering tools—not as trusted principals.

For consequential operations, I prefer architectures where:

- capabilities are explicit and scoped;
- generated changes remain reviewable;
- claims can be traced to evidence;
- tests and invariants enforce important boundaries;
- destructive or privileged actions require deliberate authority.

The useful question is not whether AI wrote a piece of code.

It is whether the resulting system can be understood, tested, reproduced, and trusted.
